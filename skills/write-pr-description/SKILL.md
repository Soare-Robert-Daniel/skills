# PR Description Structure Overview

### What changed

Explain in simple terms what changed in this pull request without being too verbose or technical. Focus on the high-level changes and their impact.

### Mermaid diagram

If applicable, include a mermaid diagram to illustrate the changes made in this pull request. This can help reviewers visualize the flow or structure of the code.

### Data transformation

If applicable, describe any data transformations that occurred as a result of the changes made in this pull request. This can include changes to data structures, formats, or any other relevant information.

If possible, also showcase the before and after of the data transformation to help reviewers understand the impact of the changes.

### QA instructions

If applicable, provide clear and concise instructions for quality assurance testing. This can include steps to reproduce the issue, test cases, or any other relevant information that will help reviewers verify the changes made in this pull request.

### PR metadata

Include any relevant metadata for the pull request, such as issue numbers, related pull requests, or any other relevant information that will help reviewers understand the context of the changes made in this pull request.

Also use native GitHub features like linking issues and pull requests to provide additional context for reviewers since they can easily navigate to the related issues and pull requests.

## Do not include

- Avoid including any sensitive information, such as passwords or API keys, in the pull request description. This can pose a security risk and should be avoided at all costs.
- Avoid including any irrelevant information that does not pertain to the changes made in this pull request. This can include personal opinions, unrelated code snippets, or any other information that does not provide value to the reviewers.
- Avoid including any unnecessary technical jargon or complex explanations that may confuse reviewers. Instead, focus on providing clear and concise explanations that are easy to understand.
